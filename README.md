# تجربة رصد Facebook لكشيدة

تطبيق Python صغير للمصادر الخمسة التي اختارها المستخدم: رصد، اليوم السابع، مزيد، وجروبان عامان. يجمع عبر SocialAPIs، ويحفظ هوية المنشورات في SQLite، ويعرض فلاتر ومعاينة Telegram. مجمع الأخبار الأساسي يستخدم المكتبة القياسية. خدمة الديمو الدائم تستخدم psycopg للاتصال بـPostgreSQL. Python 3.11+.

## عرض التجربة للشركاء من Telegram

افتح https://t.me/test_kashida_bot ثم اكتب `/start` للتعليمات. `/sources` للمصادر وأسمائها وروابطها وعدد المنشورات المحفوظة، و`/demo` لجميع المنشورات المحفوظة مرتبة حسب المصدر وبالأحدث داخله. أُضيف `/trends` لنشرة موضوعات وهاشتاجات مصر المحفوظة. حُذفت أوامر cost وsample. يمكن إعادة `/demo` بعد30 ثانية. تعرض رسالة الخبر النص والوسيط المتاح واسم المصدر والمنصة ونوع المحتوى و«تم نشره» و«تم رصده» بتوقيت القاهرة ورابط الأصل. النص الطويل يكمل في رسالة تالية. جميع أوامر العرض تستهلك صفر طلبات SocialAPIs.

البوت الآن يستقبل الأوامر عبر Webhook مستضاف على Vercel، ويقرأ النسخة المحفوظة من Neon. لا يحتاج تشغيل Actions أوجلسة لمدة ساعة، ولا يوجد سقف100 رسالة للجلسة. يظل `/demo` قابلًا للإعادة بعد30 ثانية لكل شخص، ويعمل لكل محادثة خاصة يبدأها المستخدم. مهمة الاستقبال القديمة أُوقفت لتجنب تشغيل poller منافس. التفاصيل في [PERSISTENT_DEMO.md](PERSISTENT_DEMO.md).

يسّرع `/demo` الصور القصيرة عبر ألبومات تصل إلى10 صور للطلب، مع تعليق مستقل لكل خبر. النصوص الطويلة والفيديوهات تمر عبر مسار الإرسال السابق. إذا رفض Telegram ألبومًا رفضًا مؤكدًا يعود للإرسال الفردي؛ لا يكرر إرسالًا ذا نتيجة مجهولة. يحفظ file_id بعد نجاح الوسيط لإعادة استخدامه. `/trends` يعرض قوائم قصيرة للترندات والبحث، ثم عناوين مواضيع المنشورات وروابطها، ويجمع المتشابه منها. يستبعد هاشتاج اسم المصدر مثل #مزيد من هاشتاجات الأخبار. الربط محلي بالكلمات المشتركة وTF-IDF وإشارات الترندات، وليس نموذجًا دلاليًا مدربًا أوإثباتًا للتنسيق.

تجهيز العينات القديم كان يستعيد المحفوظ من Artifact باسم demo-media-cache-v2، مدة الاحتفاظ3 أيام. نسخة الديمو الدائم نُقلت إلى Neon، ولا تعتمد على بقاء Artifact. تستورد الترقية النسخة السابقة أيضًا. إذا لم توجد نسخة صالحة أوعند اختيار refresh_samples، يجلب بحد5 طلبات منشورات وطلبين لأسماء الجروبات، سقف7 Credits. يحتفظ بالمنشورات السابقة ويحدث المكرر بهوية المصدر والمنشور. تُحفظ أسماء المصادر المحلولة في data/demo_sources.json. إذا تعذر جلب اسم جروب، يظهر معرّفه بدل اسم تخميني. النصوص والوسائط داخل data/demo_media_samples.json وليست Git. يعاد استخدام Telegram file_id بعد نجاح الإرسال. إذا لم يتوفر ملف صالح يبقى النص والرابط.

السحب اليدوي الآخر متاح من **Manual Facebook probe** ويستهلك الرصيد. تغيير المصادر يتم في `sources.json`، ويلزم تجديد عينات العرض بعد تغييره. خدمة الديمو الدائم وقاعدتها نُشرتا؛ جمع Facebook الدوري يظل غير مفعل. لا يوجد أمر عام يسمح للزوار باستهلاك مفتاح Facebook.

## التجربة من GitHub

أضف Repository Secrets:

| الاسم | القيمة |
|---|---|
| SOCIALAPIS_API_KEY | مفتاح SocialAPIs فقط |
| TELEGRAM_BOT_TOKEN | مفتاح البوت، مطلوب للإرسال فقط |
| TELEGRAM_CHAT_ID | رقم الوجهة، مطلوب للإرسال فقط |

افتح Actions ثم **Manual Facebook probe** ثم **Run workflow**. السقف خمسة طلبات، limit=3، دون Pagination أوRetry آلي. النافذة المحلية الافتراضية ساعة. يطلب المزود التاريخ على مستوى اليوم في التجربة الفعلية، رغم وصف ISO في الوثائق، ثم يطبق التطبيق فلتر الساعة محليا. فحص الرصيد قبل وبعد الجمع مجاني ولا يدخل في سقف طلبات المحتوى. خيار Telegram مغلق افتراضيا، وعند تشغيله يرسل منشورا مؤهلا واحدا كحد أقصى إلى الوجهة المضبوطة، بعد التحقق من البوت والـChat. لا توجد جدولة دورية في GitHub. فحص التكامل الأول يتحقق من رصيد SocialAPIs مجانا، ويرسل رسالة Telegram تجريبية واحدة فقط إن كانت بيانات البوت والوجهة مضبوطة. لا يجلب منشورات مدفوعة.

بعد التشغيل نزّل Artifact باسم facebook-probe-preview وافتح preview.html لتجربة فلاتر المصدر ونوع المحتوى والكلمات والفترة والتفاعل. المعاينة المحمولة تخفي نصوص الجروبات وتحذف أرقام الهواتف، وتختصر نصوص الصفحات، ولا تحتوي ملفات الوسائط أوالبيانات الخام. لا يستهلك فتحها رصيدا.

**حالة Actions مؤقتة:** كل تشغيل يبدأ SQLite جديدة. منع التكرار بين التشغيلات المستمرة يحتاج قاعدة دائمة على جهازك أوVPS، لا هذه البيئة المؤقتة. إعادة تجربة Telegram يدويًا قد تعيد منشورًا أرسل في تشغيل GitHub سابق.

## التشغيل المحلي

```bash
python monitor.py collect --max-calls 5
python monitor.py serve
```

الأمر الأول يطلب المفتاح بإدخال مخفي إن لم يكن SOCIALAPIS_API_KEY موجودا في البيئة. الواجهة المحلية http://127.0.0.1:8765 . الفلترة وعرض البيانات محليان، دون طلبات للمزود. .env.example قالب فقط ولا يحمل التطبيق .env تلقائيا. يخزن data/ محليًا، ولا يرفعه Git.

للإرسال، عيّن TELEGRAM_BOT_TOKEN وTELEGRAM_CHAT_ID في بيئتك، ثم:

```bash
python monitor.py send --max-messages 1
```

يتحقق من getMe وgetChat قبل الإرسال. يحاول إرسال صورة أوفيديو عند وجود رابط مباشر مناسب، وإلا يرسل النص والرابط الأصلي. فشل وسائط مؤكد قد يرجع إلى رسالة نصية. لا يعيد الطلب بعد timeout غامض حتى لا يكرر رسالة وصلت بالفعل. الحالة unknown تحتاج مراجعة بشرية.

## الفلاتر والحقول

settings.json يضبط: media_types، include_any، exclude_any، minimum_reactions، require_text، lookback_minutes. الكلمات قواعد بسيطة ولا تستخدم API ذكاء اصطناعي. يمكن تشغيل فيديو فقط أوصور فقط، لكن الفلتر يختار من المنشورات المجموعة؛ لا يجلب كل فيديوهات المصدر تاريخيا. Reels قد تحتاج Endpoint مستقلا لم نفعله لتوفير الرصيد.

فلتر after_time يرسل YYYY-MM-DD، ولا نعد بأن المزود يرجع كل منشورات النافذة الزمنية.

نحفظ المعرف الأصلي والرابط والنص والتوقيت ونوع الوسائط وروابطها والتفاعل. null يبقى قيمة غير متاحة. بعض الوسائط لا يرجع لها رابط ملف، وقد تنتهي الروابط. إعلان المزود نوع Video دون ملف لا يعني أن تنزيل الفيديو نجح. الوقت values.publish_time لم تثبت دلالته الدقيقة في المنشورات المعاد نشرها. عودة has_next لا تثبت اكتمال آخر نصف ساعة، وتظهر كاحتمال نقص.

الهوية source_id + post_id. تحديث النص يحدث السجل، ولا يحذف منشورا متطابقا على مصدر آخر. سجل تسليم مستقل يمنع إعادة الإرسال لنفس الوجهة في قاعدة SQLite الدائمة. لا توجد آلية retries خلفية أوخدمة إنتاجية مضمونة في هذه التجربة.

هذا الحساب لطلب أساسي واحد في المتابعة. Pagination أوزيادة limit تضيف تكلفة. لا تنخفض تكلفة الفحص لأن المصدر لم ينشر. البنية والاستضافة خارج الأرقام. السقف المحلي للتجربة 100 Credit/شهر و5 طلبات للتشغيل، قابل للضبط. سقف الشهر يتطلب نفس SQLite المستمرة؛ لا يجمع استهلاك تشغيلات Actions المؤقتة.

```bash
python monitor.py cost
python -m unittest discover -s tests -v
```

للتشغيل المستمر لاحقا يستخدم cron كل نصف ساعة مع SQLite دائمة وقفل يمنع التداخل، وحد إنفاق. جمع Facebook الدوري غير مفعل؛ خادم الديمو المحفوظ متاح عبر Webhook.

المراجع: https://socialapis.io/pricing وhttps://socialapis.io/openapi.json وhttps://core.telegram.org/bots/api . هذه خدمة بيانات طرف ثالث وليست Meta Graph API. اختبار مصدر محدود لا يثبت التغطية الشاملة أوحقوق إعادة توزيع المحتوى؛ يراجع استخدامها قبل البيع.

## الحلقة الدورية الاختيارية

`python scheduler.py --cycles 2` يشغل دورتين بفاصل settings.interval_minutes، الافتراضي30 دقيقة. لا يبدأ تلقائيا. يحتاج المفتاح في البيئة لتجنب إعادة طلبه. يضيف `--send` الإرسال الصريح، بسقف رسالة واحدة لكل دورة. يستخدم قاعدة مستمرة وقفلًا يمنع تداخل حلقتين. سقف التجربة100 Credit/شهر سيوقف الجمع قبل تشغيل واسع. لا ترفع السقف أوتضيف مصادر كثيرة قبل تحديد ميزانية. للتجربة الأولية استخدم دورة واحدة.

الرصيد بعد أحدث سحبة فعلية187. جلب المحتوى من المصادر الخمسة وربط Telegram عبر GitHub Secrets نجحا؛ ملفات الفيديو المباشرة لم تثبت. راجع LIVE_RESULTS.md لسجل الأدلة.

## شكل الرسالة وتجربة المصادر الخمسة

الرسائل تعرض المصدر بخط بارز، والمنصة، ونوع المحتوى بالعربي، وتاريخ النشر ووقت الرصد بصيغة عربية بتوقيت Africa/Cairo مع مراعاة التوقيت الصيفي. لا نحول وقت الرصد إلى وقت نشر إذا كان النشر غائبا. دلالة تاريخ المحتوى المعاد مشاركته تظل غير مثبتة؛ حُذفت الملاحظة من عرض الخبر بطلب المستخدم، وبقيت حالة البيانات محفوظة.

الفحص Five-source Telegram sample يجمع مرة واحدة من المصادر الخمسة، ثم يختار منشورًا لكل مصدر، بسقف خمسة طلبات محتوى. يختار أحدث تاريخ في العينة المتاحة، لا أول عنصر. إذا لم تتوافر عينة حديثة يمكنه عرض عينة أقدم للاختبار؛ التاريخ ظاهر. وإذا فشل المصدر يرسل حالته. هذا وضع اختبار، وليس تغييرًا لفلتر الأخبار الجديدة في التشغيل الدوري. المقتطفات محدودة في هذا الفحص القديم؛ عرض /demo يستخدم نص الخبر من ملف البيانات المحفوظ.

تُقص النصوص قبل تحويلها إلى HTML مع إبقاء الرابط وعناوين البيانات، وتُراعى حدود رسائل Telegram وتعليقات الصور. لا توجد جدولة مفعلة تلقائيا.
